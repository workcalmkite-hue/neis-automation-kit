# 5. MCP 연결하기 (말로 시키려면)

MCP를 연결해 두면 클로드 코드에서 **말로** 출결을 다룰 수 있습니다.

```
출결 캘린더 9개 만들어줘
7번 박지우 오늘 2교시부터 질병조퇴 넣어줘
9월 출결 뭐뭐 있는지 보여줘
```

---

## 왜 이게 따로 필요한가요

**구글 공식 캘린더 MCP로는 캘린더를 못 만듭니다.**

클로드 커넥터에 있는 구글 캘린더 MCP는 도구가 9개인데
(`list_events` · `create_event` · `update_event` · `delete_event` …)
전부 **일정**을 다루는 것이고 **캘린더 자체를 만드는 도구가 없습니다.**
많이 쓰이는 서드파티 서버(`nspady/google-calendar-mcp`, 도구 12개)도 마찬가지입니다.

그래서 이 저장소에 `mcp_server.py`를 넣어 그 자리를 채웠습니다.

---

## 연결하기

연결 정보가 담긴 **`.mcp.json`이 이미 저장소에 들어 있습니다.**
클로드 코드는 폴더를 열 때 이 파일을 자동으로 읽습니다.

1. **[01](01_처음-준비.md)·[02](02_구글-연동.md) 를 먼저 끝내세요.**
   MCP는 설정 마법사가 만들어 둔 구글 토큰을 그대로 씁니다 — 따로 로그인하지 않습니다.
2. VS Code에서 **이 저장소 폴더를 연 상태**인지 확인합니다.
   왼쪽 목록에 `mcp_server.py`가 보이면 맞습니다.
3. ⭐ **VS Code를 껐다 켭니다.**
   MCP 목록은 **클로드 코드가 시작할 때 한 번만** 읽습니다.
   껐다 켜지 않으면 아무리 기다려도 안 붙습니다 — 고장이 아닙니다.
4. 클로드 코드를 열면 **"이 폴더의 MCP 서버를 신뢰하시겠습니까?"** 를 물어봅니다 → **승인**.
5. 클로드 코드에 `/mcp` 를 쳐서 **`나이스출결`** 이 목록에 있는지 확인합니다.

> `.mcp.json`이 왼쪽 목록에 안 보이나요? **점(.)으로 시작하는 파일은 숨김 파일**이라
> 안 보이게 설정된 경우가 있습니다. 파일이 없는 게 아닙니다.
> 확인하려면 터미널에 `dir .mcp.json`.

---

## 들어오는 도구 4개

| 도구 | 하는 일 | 이렇게 말하면 됩니다 |
|---|---|---|
| `make_attendance_calendars` | 캘린더 9개 만들기 (이미 있으면 건너뜀) | "출결 캘린더 만들어줘" |
| `check_attendance_calendars` | 9개 다 있는지 확인만 (아무것도 안 만듦) | "출결 캘린더 다 있나 확인해줘" |
| `add_attendance` | 출결 일정 넣기 — 제목 형식 자동 변환 | "7번 박지우 2교시부터 조퇴" |
| `list_attendance` | 기간별 출결 모아보기 (읽기만) | "9월 출결 보여줘" |

### `add_attendance`가 형식을 대신 맞춥니다

`{번호} {이름} {분류} (교시)` 규칙을 외우지 않아도 됩니다.

- 교시를 `2교시`처럼 숫자만 줘도 **분류에 맞는 방향**을 붙입니다
  → 조퇴는 `(2교시~)`, 지각은 `(~2교시)`
- 결석 기간을 `9/1~9/3`으로 주면 구글 캘린더의 **종료일 +1일**(`9/4`)을 알아서 처리합니다
- 조퇴·지각은 여러 날로 넣지 않고 항상 하루로 처리합니다

규칙 자체는 [03_캘린더-입력규칙.md](03_캘린더-입력규칙.md) 참고.

## 안 붙을 때

| 증상 | 해결 |
|---|---|
| `/mcp` 목록에 `나이스출결`이 없다 | **VS Code를 껐다 켜지 않은** 경우가 대부분입니다 |
| 서버가 시작하다 죽는다 | `.venv`가 없는 것입니다. `.\setup.ps1` 을 먼저 돌리세요 |
| `구글 계정이 연동되지 않았습니다` | `python setup_wizard.py` 를 아직 안 돌렸습니다 |
| 경로 문제로 안 뜬다 | `.mcp.json`의 `command`를 **절대경로**로 바꿔보세요<br>예: `C:/Users/내계정/neis-automation-kit/.venv/Scripts/python.exe` |

### 왜 `./` 가 없으면 안 되는가 (실측)

윈도우는 실행 파일 경로를 받으면 먼저 **"이게 경로인가, 아니면 이름인가"** 를 판단합니다.
그 판단 기준이 **역슬래시(`\`)가 있는지** 또는 **`.` 으로 시작하는지** 입니다.
**슬래시(`/`)만으로는 경로로 인정하지 않습니다.**

경로가 아니라 "이름"으로 판단하면, 윈도우는 **현재 폴더를 보지 않고 `PATH`만 뒤집니다.**
`PATH` 어디에도 `.venv/Scripts/python.exe` 라는 이름의 파일은 없으니 못 찾는 것입니다.

실제로 같은 파일을 형태만 바꿔 실행해 본 결과입니다.

| 적은 형태 | 결과 | 이유 |
|---|---|---|
| `직접놓은.exe` (현재 폴더에 진짜 있음) | ❌ | 구분자가 없어 이름으로 판단 → `PATH`만 뒤짐 (현재 폴더는 안 봄) |
| `.venv/Scripts/python.exe` | ❌ | 슬래시는 구분자로 안 쳐줌 → 역시 이름으로 판단 |
| `.venv\Scripts\python.exe` | ✅ | 역슬래시가 있으니 경로로 판단 → 현재 폴더 기준으로 찾음 |
| `./.venv/Scripts/python.exe` | ✅ | `.` 으로 시작하니 경로로 판단 |
| `C:/Users/.../python.exe` | ✅ | 절대경로 |

그래서 `.mcp.json` 에는 **`./` 를 붙이거나 절대경로**로 적습니다.
`.json` 파일 안에서는 역슬래시를 `\` 로 두 번 써야 해서, `./` 쪽이 덜 헷갈립니다.

**증상이 조용합니다.** 경로가 틀리면 오류 메시지가 뜨는 게 아니라
`/mcp` 목록에 그냥 **안 나타납니다.** 그래서 "껐다 안 켰나?" 하고 헤매기 쉽습니다.

## MCP 없이 쓰려면

MCP는 편의 기능입니다. 연결하지 않아도 전부 됩니다.

```powershell
.\.venv\Scripts\python.exe setup_wizard.py   # 캘린더 9개 생성 포함
.\.venv\Scripts\python.exe main.py --dry-run # 출결 확인
.\.venv\Scripts\python.exe main.py           # 나이스 입력
```

캘린더만 따로 만들고 싶고 파이썬도 안 깔았다면, 앱스스크립트로 만드는 방법이 있습니다
— [03_캘린더-입력규칙.md](03_캘린더-입력규칙.md) 아래쪽 참고.
