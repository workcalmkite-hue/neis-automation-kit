# 본인 복무(근무상황) 신청

> **학생 출결과 헷갈리지 말 것.**
> **시각**(15:20)으로 말하면 → 본인 근무상황신청 (이 스킬)
> **교시**(5교시~)와 **학생 이름**으로 말하면 → 학생 출결 ([[출결등록]] · [[나이스출결]])

## 1. 값 정하기 — 질병이냐 아니냐로 대분류가 갈린다

| | 질병 조퇴 | 일반 조퇴 |
|---|---|---|
| **대분류** | 병가 | 연가 |
| **소분류** | `병조퇴` (지각 `병지각` / 외출 `병외출`) | `조퇴` (지각 `지각` / 외출 `외출`) |
| 차감 | 병가 일수 | 연가 (`금년도연가` 자동 지정) |

> 대분류 목록에 "조퇴"라는 항목은 **없다.** 항상 병가/연가 아래 소분류다.
> 대분류 전체: 연가 / 병가 / 공가 / 특별휴가 / 대체휴무 / 결근 / 연수 / 기타

사용자가 질병 여부를 안 밝히면 **물어본다.** 사유를 안 말했으면 한 번 확인한다.

| 항목 | 값 |
|---|---|
| 시작일시 | 해당 날짜 + 조퇴 시각 |
| 종료일시 | 같은 날 **퇴근 시각** (학교마다 다름, 보통 16:20 또는 16:30) |
| 신청시간 | 시스템이 자동 계산 |
| 연락처 | 설정의 `contact` |
| 결재선 | 설정의 `approval_line` (나이스에 미리 저장해 둔 프리셋 이름) |

날짜는 **직접 계산하지 말고 코드로 확인한다** — "다음주 화요일" 같은 표현은 요일까지 맞는지 본다.

## 2. 실행 — 스크립트가 먼저다

```powershell
.\.venv\Scripts\python.exe main_bokmu.py `
  --type 조퇴 --date 2026-09-10 --start 15:00 --end 16:20 --reason "병원 진료"
```

- `--type` : `지각` / `조퇴` / `외출`
- `--dry-run` : 폼만 채우고 **승인요청을 누르지 않는다** (처음 쓸 때 권장)
- `--contact` / `--approval-line` : 설정값 대신 이번만 다른 값을 쓸 때

연락처·결재선이 설정에 없으면 스크립트가 **안내하고 멈춘다.**
`setup_wizard.py` 를 다시 돌려 채우게 한다.

## 3. 스크립트가 안 될 때 — 로그인해 둔 크롬을 직접 조작

화면 구조가 바뀌어 스크립트가 멈추면 아래 4절대로 `neis_session.py` 로 로그인해 두고,
`neis_cdp.py` 스니펫으로 아래 순서를 조작한다 (스니펫은 파이썬 문법).

1. 인증서 로그인 (아래 4절)
2. 좌측 `복무` → `개인근무상황관리`
   - ⚠️ **사이드바 클릭이 오버레이(`.cl-formlayout-vertical-separator`)에 막힌다.**
     `a[title="복무"]` 를 잡고 **좌표 클릭**: `.click(position={"x": 20, "y": 8})`
   - 메뉴의 접근성 텍스트는 `"개인근무상황관리 1단계"` 라 정확히 일치 검색은 0건이다
3. 상단 `신청(새 창 열림)` → `근무상황신청` 다이얼로그
4. `근무상황대분류` 콤보 → `병가`(또는 `연가`) → `근무상황소분류` → `병조퇴`
   - 커스텀 콤보라 `select_option` 이 안 먹는다. 클릭해서 열고 옵션을 클릭
5. **날짜가 오늘이 아니면** `달력으로 날짜 선택` 클릭 → 달력에서 날짜 버튼
   (`aria-label` 형식: `2026년 9월 10일 목요일`). **`fill()` 쓰면 마스크가 깨진다**
6. `시작 시`·`시작 분` 콤보 선택
   - ⚠️ **분 콤보는 가상 스크롤이라 `00`·`05`가 목록에 안 보인다.** 콤보를 연 상태에서
     `ArrowUp` 으로 올라간 뒤 `Enter`. 스크롤·`scrollTop`은 안 먹는다
7. `연락처`: 마스크 칸이라 `fill()`이 깨진다 → 클릭 → `Ctrl+A` → `Delete` →
   `page.keyboard.type("01012345678", delay=120)`
8. `사유 또는 용무` 입력. `목적지`는 비워도 상신된다
9. **상신 전 검증**: 상단 `근무상황신청목록` 그리드의 `aria-label`을 읽어
   근무상황·시작·종료·신청시간이 의도대로인지 확인
10. `승인요청` → `기안문서상신` → `개인결재선` → 설정의 프리셋 이름 클릭 → `지정`
11. **위임결재자지정 팝업이 뜨면** (결재자 부재 시): 대결자 행의 **체크박스를 체크한 뒤**
    `결재자 지정`. 체크 안 하고 버튼만 누르면 `"결재자로 지정할 사용자를 선택하세요"` 알림만 뜬다
    - 원결재자로 보낼지 대결자로 보낼지는 **학교 관행에 따라 다르다** → 사용자에게 확인
12. `상신` → 알림 3개를 순서대로 `확인`
    ("최종 결재자 이외의 결재자는 검토로 변경합니다" / "상신하겠습니까?" / "상신을 완료하였습니다")
13. **검증**: 목록에서 `조회` → 해당 행이 `상신(진행)` 인지 `aria-label`로 읽어
    **그 값을 사용자에게 그대로 보고한다**

## 4. 인증서 자동 로그인 (모든 나이스 스킬 공통)

> ⚠️ **Claude Code 의 브라우저 도구(Playwright MCP)로 나이스를 열지 않는다.**
> 로그인 창이 «보안프로그램이 로딩중»에서 멈추고 암호칸이 끝내 안 뜬다 (2026-09-11 실측).
> 크롬이 https 페이지에서 127.0.0.1(보안모듈) 접근을 막기 때문이고, 그걸 푸는 크롬 설정이 `neis_session.py` 에 들어 있다.

1. **먼저 점검** (크롬을 띄우지 않는다)
   ```powershell
   $env:PYTHONUTF8='1'; .\.venv\Scripts\python.exe neis_session.py --check
   ```
   `❌` 가 나오면 그 아래 안내대로 고친다 — 대부분 **사용자가 직접** `fix_cert.py` 를 돌리면 된다.
   사용자에게 암호를 대화창에 치게 하지 않는다
2. **로그인해 두기** — **백그라운드로** 실행하고, 출력에 `READY port=9222` 가 찍힐 때까지 기다린다
   ```powershell
   $env:PYTHONUTF8='1'; .\.venv\Scripts\python.exe neis_session.py
   ```
   - 인증서 목록에서 설정 이름이 든 행이 **정확히 1개이고 만료 전일 때만** 암호를 넣는다.
     0개·여러 개·만료면, 그리고 목록이나 만료일 글자를 못 읽어도 **암호를 넣기 전에** 멈추고 창에 보이는 인증서 목록을 찍는다
   - 암호를 넣었는데 로그인이 안 되면 **다시 시도하지 않는다**
   - 자동 로그인이 막히면 `⏸` 줄과 고치는 법이 찍히고, **창을 닫지 않은 채 5분 동안 사람이 직접 로그인하기를 기다린다.**
     → 사용자에게 `⏸` 내용을 그대로 보여 주고 «열린 크롬 창에서 직접 로그인해 주세요»라고 말한다. 로그인되면 그대로 `READY` 로 이어진다
   - 그 사이 뜨는 알림·확인창은 스크립트가 닫지 않는다 (`💬 화면 알림` 줄로 글자만 찍힌다) → 사용자가 크롬 창에서 직접 누른다
   - 자동 로그인 중에 예상 못 한 오류가 나도 창을 닫지 않고 같은 수동 대기로 넘어간다
   - 출결 입력·검증(`main.py`·`verify_attendance.py`)이 **같은 크롬 프로필**을 쓰는 중이면 끊지 않고 `❌` 로 멈춘다 — 그 작업이 끝난 뒤 다시 실행
   - `포트 9222 을 다른 프로그램이 쓰고 있습니다` 면 `$env:NEIS_CDP_PORT='9333'` 을 넣고 `neis_session.py`·`neis_cdp.py` 둘 다 같은 창에서 실행
   - 로그인 여부는 화면의 `로그아웃` 글자로 본다 (담임이 아니어도 된다)
3. **조작은 스니펫 파일로** — 스니펫 안에서 `page`·`ctx` 를 바로 쓴다 (최상위 `await`, `return` 가능)
   ```powershell
   $env:PYTHONUTF8='1'; .\.venv\Scripts\python.exe neis_cdp.py 스니펫.py
   ```
4. 끝나면 `neis_session.py` 프로세스를 종료한다 (크롬 창도 같이 닫힌다).
   창이 남아 있어도 다음 실행 때 **전에 `neis_session.py` 로 연 창만** 알아서 닫고 새로 띄운다
5. **암호는 절대 화면에 찍지 않는다.** 암호는 스크립트가 keyring 에서 «직접» 읽는다.
   사람도 LLM 도 그 값을 볼 일이 없다 — 꺼내서 넘기지 마라.

   ⚠️ 예전에 이 자리에 `print('CERT_PASSWORD='+keyring.get_password(...))` 가 적혀 있었다.
   그걸 실행하면 암호가 터미널과 대화 기록에 그대로 남는다. **쓰지 마라** (2026-09-11 삭제).

   확인이 필요하면 «있다/없다» 만 보는 1번 점검(`neis_session.py --check`)을 돌린다 — 암호는 안 찍힌다.

## 5. 주의사항 (실제로 겪은 것)

- **무거운 DOM 순회 금지.** `document.querySelectorAll('*')` 를 돌리면 렌더러가 죽어
  페이지가 `about:blank`가 되고 세션이 끊긴다. 값 확인은 `aria-label` 셀렉터로 좁혀서
- **전역 `getByRole('button', {name:'닫기'})` 클릭 금지.** 브라우저 창 자체가 닫힌 적이 있다
- 첫 로그인 시 **공지 팝업**이 사이드바를 덮을 수 있다. 좌표 클릭으로 진행하거나
  그 다이얼로그만 `style.display='none'`
- 사용자가 브라우저를 같이 쓰고 있을 수 있다. **다른 탭을 건드리지 않는다**
